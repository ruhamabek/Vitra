# AI Agent Setup & Prompt

Vitra was built from the ground up to be operated natively by AI agents. Instead of forcing agents to hallucinate CSS styles or inspect binary design files, Vitra gives agents a deterministic Visual AST, declarative specifications (`design.md`), headless audits, visual rendering, and version control.

---

## 1. Quick Agent Harness Setup

Choose your agent harness below to configure Vitra tools and system instructions:

### Cursor (`.cursorrules` or System Prompt)
Place the system prompt below into `.cursorrules` in your project root, or include it in your Cursor project rules:
```bash title="terminal"
cat prompt.md >> .cursorrules
```

### Claude Desktop (`claude_desktop_config.json`)
Add the Vitra MCP Server to your Claude Desktop configuration file (`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS or `%APPDATA%\Claude\claude_desktop_config.json` on Windows):

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "vitra": {
      "command": "vitra",
      "args": ["mcp", "./my-design.vitra"]
    }
  }
}
```

### Cursor (`.cursor/mcp.json`)
You can configure MCP in Cursor via `.cursor/mcp.json` or Cursor Settings → Features → MCP:

```json title=".cursor/mcp.json"
{
  "mcpServers": {
    "vitra": {
      "command": "vitra",
      "args": ["mcp"]
    }
  }
}
```

### Antigravity / AGY
Antigravity automatically discovers skills in `.agents/skills/` or directly from GitHub:
```bash title="terminal"
# Install directly from the GitHub repository
npx skills add ruhamabek/Vitra

# Or access directly via local skills directory
cat .agents/skills/vitra/SKILL.md
```

## 1. Project Discovery & Core Architecture

When interacting with a project:
1. Locate the `.vitra` project directory (e.g. `./my-project.vitra` or `./design.vitra`) containing:
   - `vitra.json`: Project manifest, artboard definitions, and token references.
   - `scene/`: Declarative JSON files defining artboards, frames, text, shapes, and components.
   - `tokens/`: W3C Design Tokens (`tokens.json`) for colors, typography, spacing, and shadows.
   - `.history/`: Content-addressable Git object store (`objects/`, `refs/`, `HEAD`, `index`).
2. If no `.vitra` directory exists, initialize one:
   ```bash
   vitra init ./my-project.vitra --name "Design System"
   ```
3. Inspect current canvas state:
   ```bash
   vitra inspect ./my-project.vitra
   vitra status ./my-project.vitra
   ```

## 2. The Vitra Autonomous Design Loop

When creating or modifying UI components, ALWAYS follow this 6-step loop:

1. **Inspect Scene Graph**:
   Query existing nodes or artboards:
   ```bash
   vitra inspect <projectDir>
   vitra spec <projectDir> --node <nodeId>
   ```
2. **Compose Declarative Specification (`design.md`)**:
   Write or modify UI using Vitra's clean, indentation-based `design.md` grammar (detailed below).
3. **Atomic Ingestion**:
   Mount the component into the project:
   ```bash
   vitra apply <projectDir> component.md --parent <artboardOrFrameId>
   ```
4. **Visual Verification**:
   Render the component to high-resolution PNG for sensory inspection:
   ```bash
   vitra render <projectDir> --node <nodeId> --out preview.png --scale 2
   ```
5. **Headless Accessibility Audit**:
   Verify WCAG 2.1 contrast ratios and container boundary overflow:
   ```bash
   vitra audit <projectDir> --strict
   ```
   If any violations occur, adjust colors or layout dimensions and re-run.
6. **Commit & Version Snapshot**:
   Stage and record the change with semantic intent and rationale:
   ```bash
   vitra add <projectDir> .
   vitra commit <projectDir> -m "feat(ui): add responsive user profile card" --rationale "Updated layout to flex-wrap with WCAG AA compliance"
   ```

## 3. Declarative Specification Grammar (`design.md`)

Use 2 spaces per indentation level. Properties are enclosed in brackets `[...]`.

### Frame / Artboard
```markdown
- Frame: <id> [w: <num|fill|hug>, h: <num|fill|hug>, dir: <vertical|horizontal>, gap: <num>, pad: <num>, fill: <hex|$token>, r: <num>, stroke: <hex|$token>, strokeWidth: <num>, align: <start|center|end|stretch>, justify: <start|center|end|space-between>]
```
- `dir`: `vertical` (column) or `horizontal` (row).
- `w`, `h`: Fixed pixel numbers or responsive keywords (`fill` to expand into parent, `hug` to shrink-wrap children).
- `gap`: Space between children in pixels.
- `pad`: Internal padding in pixels (or granular `padT`, `padR`, `padB`, `padL`).
- `align`: Cross-axis alignment (`start`, `center`, `end`, `stretch`).
- `justify`: Main-axis distribution (`start`, `center`, `end`, `space-between`).

### Text
```markdown
- Text: <id> [text: "<content>", size: <num>, weight: <400|500|600|700>, fill: <hex|$token>, wrap: <true|false>, maxW: <num>, lineHeight: <num>]
```
- `size`: Font size in px.
- `weight`: Numeric weight (400=Regular, 500=Medium, 600=SemiBold, 700=Bold).
- `wrap`: `true` or `false`. Always set `wrap: true` with `maxW` for dynamic text longer than 3 words.

### Icon
```markdown
- Icon: <id> [icon: "<name>", size: <num>, color: <hex|$token>]
```
- `icon`: Any icon name from the Lucide library (e.g. `heart`, `search`, `bell`, `arrow-up-right`, `check`, `shopping-cart`). Do NOT use raw emoji characters.

### Shape
```markdown
- Shape: <id> [shape: <rectangle|ellipse|divider>, w: <num>, h: <num>, fill: <hex|$token>, r: <num>]
```

## 4. MCP Tools Reference

When running in an MCP-equipped environment (such as Claude Desktop or Antigravity), use native JSON-RPC tools rather than raw shell commands when possible:

- `spawn_artboard`: Create a top-level canvas boundary with standard device presets (`desktop-1440`, `mobile-390`, `tablet-768`).
- `render_viewport`: Headless rasterization of canvas to PNG base64 for multimodal vision verification.
- `create_frame`: Construct auto-layout flex containers with padding, background fills, and border radii.
- `create_text`: Append typographic nodes with font tokens, sizes, and wrapping bounds.
- `create_icon`: Add crisp vector icons from the Lucide library.
- `create_shape`: Create geometric shapes, rectangles, ellipses, and horizontal/vertical dividers.
- `insert_component`: Instantiate reusable components with prop overrides.
- `update_node`: Mutate any visual or spatial property on an existing node.
- `delete_node`: Remove a node and its descendants from the scene graph.
- `move_node`: Reorder or reparent a node in the visual hierarchy.
- `register_tokens`: Ingest or update W3C DTCG design tokens.
- `set_theme`: Swap token theme collections (`light`, `dark`, `high-contrast`).
- `audit_design`: Run headless WCAG 2.1 contrast ratio and boundary overflow checks.
- `export_code`: Compile scene graph to React + Tailwind, SwiftUI, HTML/CSS, SVG, or PNG.
- `get_user_edits`: Check whether a human designer has made modifications in the browser canvas to avoid overwriting them.
- `save_project`: Persist memory state to disk.
- `load_project`: Load `.vitra` project directory into active memory.
- `commit_version`: Record version snapshot with message, model name, and rationale.
- `get_history`: Retrieve commit DAG history log.
- `diff_projects`: Compute AST-level differences between working tree and commit.

## 5. Non-Negotiable Rules & Guardrails

1. **Accessibility First**: Never mark a design task complete without running `vitra audit --strict` or `audit_design`. Contrast ratios MUST be >= 4.5:1 for normal body text and >= 3:1 for large text.
2. **Deterministic Layouts**: Always set layout directions (`vertical` or `horizontal`) explicitly on parent frames containing multiple items. Do not leave layout undefined.
3. **Responsive Sizing**: Use `w: fill` for fluid cards and containers inside columns; use `w: hug` for badges, tags, and action buttons.
4. **No Raw Emojis**: Always use `Icon` nodes with valid Lucide icon names.
5. **Respect Human Edits**: Query `get_user_edits` before applying destructive AST updates.

## 3. The Autonomous Execution Loop

```text
+-------------------+      +---------------------+      +---------------------+
| 1. Inspect AST    | ---> | 2. Compose Spec     | ---> | 3. Apply Node       |
| vitra inspect     |      | design.md           |      | vitra apply         |
+-------------------+      +---------------------+      +---------------------+
                                                                   |
                                                                   v
+-------------------+      +---------------------+      +---------------------+
| 6. Version Commit | <--- | 5. Headless Audit   | <--- | 4. Headless Render  |
| vitra commit      |      | vitra audit --strict|      | vitra render        |
+-------------------+      +---------------------+      +---------------------+
```

By following this loop, an AI agent can build entire user interfaces, adjust spacing, verify visual correctness with vision models, and guarantee zero contrast violations before committing changes to Git.
